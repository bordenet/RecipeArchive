# Recipe URL Discovery Tool - Technical Specification

## Purpose
Automated discovery and validation of recipe URLs from supported sites to maintain E2E test suite health and build historical recipe archives.

## Problem Statement
Recipe URLs frequently become stale due to:
- Content moved/deleted (404s)
- URL structure changes
- Site redesigns
- Domain sales/shutdowns

Manual URL discovery is time-consuming and error-prone.

## Core Requirements

### 1. Fresh Recipe Discovery
**Goal:** Find working recipe URLs for each supported site

**Approach:**
- **Sitemap Crawling:** Parse `sitemap.xml` files (most recipe sites publish these)
- **RSS/Atom Feeds:** Many food blogs have RSS feeds with recent recipes
- **Site Search APIs:** Use site-specific search (e.g., `site:epicurious.com recipe`)
- **Content-Type Detection:** Filter for pages with JSON-LD Recipe schema

**Output Format:**
```json
{
  "site": "epicurious",
  "urls": [
    {
      "url": "https://www.epicurious.com/recipes/food/views/...",
      "title": "Recipe Title",
      "discoveredAt": "2025-11-02T12:00:00Z",
      "hasRecipeSchema": true,
      "ingredientCount": 8,
      "instructionCount": 5
    }
  ],
  "lastUpdated": "2025-11-02T12:00:00Z"
}
```

### 2. Legacy Recipe Archive (Stretch Goal)
**Goal:** Build historical archive of recipes from each site

**Approach:**
- **Wayback Machine API:** Access archived versions of recipe pages
- **Progressive Crawl:** Start with sitemaps from different time periods
- **Deduplication:** Hash-based detection of duplicate recipes across URLs
- **Version Tracking:** Track recipe changes over time

**Use Cases:**
- Test parser backwards compatibility
- Historical recipe data research
- Detect when sites change their markup structure

### 3. URL Validation Pipeline
**Goal:** Verify discovered URLs work with our parsers

**Workflow:**
```
1. Discover URLs (sitemap/RSS/search)
2. Fetch page content
3. Check for JSON-LD Recipe schema
4. Run TypeScript parser
5. Validate extraction (min ingredients, min instructions)
6. Score quality (completeness, image presence, metadata)
7. Update test catalog if quality score > threshold
```

**Quality Scoring:**
```javascript
score = {
  hasTitle: 10,
  hasIngredients: 20,
  hasInstructions: 20,
  hasImage: 10,
  hasTimings: 10,
  ingredientCount: min(ingredients.length, 10) * 2,
  instructionCount: min(instructions.length, 10) * 2,
  // Total: 100 points max
}
```

## Implementation Design

### Tool Structure
```
tools/recipe-url-discovery/
├── discover.go              # Main discovery engine
├── validators/
│   ├── sitemap.go          # Sitemap crawler
│   ├── rss.go              # RSS/Atom parser
│   ├── wayback.go          # Internet Archive integration
│   └── quality.go          # URL quality scoring
├── cache/
│   └── discovered-urls.json # Cached results per site
└── config.yaml             # Site-specific configs
```

### Configuration (config.yaml)
```yaml
sites:
  epicurious:
    sitemapUrl: https://www.epicurious.com/sitemap.xml
    rssUrl: https://www.epicurious.com/feed/rss
    searchPattern: "site:epicurious.com recipe"
    parserName: "EpicuriousParser"
    minIngredients: 4
    minInstructions: 2
    qualityThreshold: 70

  food52:
    sitemapUrl: https://food52.com/sitemap.xml
    rssUrl: https://food52.com/recipes.rss
    searchPattern: "site:food52.com recipe"
    parserName: "Food52Parser"
    minIngredients: 5
    minInstructions: 3
    qualityThreshold: 70
```

### CLI Interface
```bash
# Discover fresh recipes for all sites
./recipe-url-discovery --discover-all

# Discover for specific site
./recipe-url-discovery --site epicurious

# Update E2E test catalog automatically
./recipe-url-discovery --update-tests

# Build legacy archive (stretch goal)
./recipe-url-discovery --archive --site epicurious --from-date 2020-01-01

# Validate existing test URLs
./recipe-url-discovery --validate-catalog
```

## Maintenance Schedule
- **Daily:** Validate existing test catalog URLs (detect 404s)
- **Weekly:** Discover new recipes from RSS feeds
- **Monthly:** Full sitemap crawl for all sites
- **Quarterly:** Archive snapshot (stretch goal)

## Error Handling
- **404 Detection:** Remove from catalog, trigger discovery for replacement
- **Parser Failures:** Log for investigation, don't auto-update catalog
- **Rate Limiting:** Respect robots.txt, implement backoff
- **Schema Changes:** Alert when parser quality scores drop significantly

## Success Metrics
- **URL Freshness:** < 5% 404 rate in test catalog
- **Parser Coverage:** 100% of supported sites have ≥2 working test URLs
- **Discovery Speed:** < 5 minutes to find replacement for failed URL
- **Quality:** Average quality score ≥ 80 for catalog URLs

## Future Enhancements
1. **ML-Based Quality Prediction:** Predict recipe quality from metadata
2. **Community Contributions:** Allow users to submit working recipe URLs
3. **Multi-Language Support:** Discover recipes in different languages
4. **Competitive Intelligence:** Track when competitors add new features
5. **Recipe Trend Analysis:** Identify trending ingredients/techniques over time

## Dependencies
- Go 1.21+ (core tool)
- Sitemap parser library (e.g., `github.com/oxffaa/gopher-parse-sitemap`)
- RSS parser (e.g., `github.com/mmcdole/gofeed`)
- Wayback Machine API client
- Existing TypeScript parser bundle (for validation)
